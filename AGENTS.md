- Admin email uses Bird via admin-only src/lib/bird.functions.ts; secrets stay server-side. Bulk is marketing only, requires explicit recipient consent confirmation, per-recipient messages, suppression checks and review. Never use SendFox.
- Inquiry replies are sent through the existing app-email service in response to a specific inquiry (src/lib/inquiry-reply.functions.ts, 'inquiry-reply' app-email template): recipient loaded server-side from the inquiry row, admin-only, every attempt logged in inquiry_replies — the app-email service forbids promotional or list sends.
- Optional SES one-person emails with real attachments go through Amazon SES v2 via admin-only src/lib/ses.functions.ts (aws4fetch SigV4, creds only in AWS_SES_* server secrets, private email-attachments bucket, every attempt in ses_send_log); SES is personal/customer-matter only, never promotional or bulk (no automated unsubscribe link) — promotional and bulk use Bird, inquiry replies stay on the app-email template.
- Paid beat licenses are stored in purchase_licenses by the payment webhook (guest buyers have no user_id); the public /licenses page only emails copies to the entered address, never displays them — prevents lookup of other people's purchases.
- Admin-generated /pay/$beatId links use the existing cart checkout and payment webhook, with server-resolved beat prices and discounts — one purchase path keeps file and license delivery consistent.
- Buyer file + agreement links are short codes: purchase_licenses.short_code (12-char base64url, unique, generated by column default) served at /d/$code; the legacy /download/$token route must stay resolvable because older emails already carry the long token — keeps links shareable without breaking delivered mail.
- Match purchase licenses only by exact payment session and beat. Never fall back by email/beat or another item in the same cart.
- Bird sends use a unique logged attempt ID and provider idempotency; unknown outcomes must not be automatically retried. Accepted is not delivered.
